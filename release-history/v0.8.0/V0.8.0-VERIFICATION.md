## Parser stress test

An 82-record synthetic set contained 80 normal rows, one row with quantity 11 and two rows with decimal dimensions. The parser returned 79 automatic rows and three review rows. No automatically accepted row had a fractional length/width or a quantity above 10.

## Browser interaction coverage

The Chromium test verified the full-row editor, live save behavior, Previous / Next navigation, table synchronization, row editor mobile-width overflow, decimal dimension rejection in the main table, review cards, 12-page simulated PDF text extraction and OCR fallback selection.

## Scope / limitations

The workshop's actual large PDF was not included in this request. Multi-page behavior is exercised with a 12-page synthetic document containing 96 rows; the scanned-PDF branch is exercised using a controlled OCR worker. These tests verify the extraction workflow and fallback logic, not recognition accuracy on every real-world scan. The user should compare parsed rows with the source before optimization and cutting.
